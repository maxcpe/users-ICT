# UI ระบบจัดการผู้ใช้

**`design.md` ที่ root คือข้อกำหนดหลักของหน้าตา** อ่านหัวข้อที่เกี่ยวข้องก่อนสร้างหรือแก้หน้าจอทุกครั้ง ตัวอย่างหน้าจอที่ตกลงแล้วอยู่ที่ `docs/design-c-all-pages.html` ถ้าตัวอย่างกับ `design.md` ขัดกัน ให้ยึด `design.md`

ส่วนกฎเรื่องสิทธิ์และข้อมูลอ่อนไหวอยู่ใน skill `user-management-dev`

## สรุปสิ่งที่ห้ามพลาด (รายละเอียดอยู่ใน design.md)
- **โหมดมืดอย่างเดียว** `color-scheme: dark` ไม่มีโหมดสว่าง ไม่ใช้พื้นขาวหรือการ์ดสีทึบสว่าง
- **ใช้ token เท่านั้น** (design.md หัวข้อ 2) ตั้งใน `src/app/globals.css` และ map เป็น `@theme` ห้ามเขียนค่าสีหรือขนาดตรงๆ เช่น `bg-[#ff2bd6]` ถ้าต้องมี token ใหม่ ให้เพิ่มใน design.md ก่อน
- **ตัวอักษรที่มีสีใช้ `*-ink` เสมอ** ห้ามใช้ `--pink` / `--cyan` / `--violet` เป็นสีตัวอักษร
- **แสงเรืองและไล่สีใช้ได้เฉพาะ** หัวข้อ (1–2 คำ) ตัวเลขสรุป ปุ่มหลัก และสิ่งที่กำลังเลือก ห้ามใช้กับข้อความยาว ตาราง และช่องกรอก
- **สีสถานะ** (ok / warn / bad) ใช้บอกความหมายเท่านั้น ห้ามใช้ตกแต่ง และต้องมีไอคอนหรือข้อความคู่กันเสมอ
- **ฟอนต์**: Kanit กับหัวข้อหน้า Prompt กับส่วนอื่น โหลดผ่าน `next/font/google` ห้ามใช้ letter-spacing กับข้อความไทย
- **อีโมจิ** ใช้นำหน้าได้ (ไอคอนระบบ ป้ายบทบาท) ห้ามใช้แทนข้อความ
- **การเคลื่อนไหว**: transition 150ms กับสีและเงาเท่านั้น ไม่มีอะไรเคลื่อนไหวต่อเนื่องนอกจากโลโก้หน้าเข้าสู่ระบบ และต้องเคารพ `prefers-reduced-motion`

## การเข้าถึงได้ (design.md หัวข้อ 9)
- ข้อความผ่าน WCAG AA ทั้งบน `--bg` และบนการ์ดกระจก
- พื้นที่กด ≥ 44px ช่องกรอก 16px บนมือถือ
- focus ring ฟ้าชัดทุกจุดที่กดได้
- ตัวเลือกในตารางมี `aria-label` ที่บอกชื่อคน
- error ของฟอร์มผูกด้วย `aria-describedby` + `aria-invalid` และประกาศผ่าน `aria-live`
- skill ช่วยตรวจ: `fixing-accessibility`, `baseline-ui`

## พฤติกรรมของหน้าจอ (จาก spec)
- ตั้งระดับสิทธิ์ด้วยตัวเลือกเท่านั้น ห้ามมีช่องให้พิมพ์ตัวเลข ค่าที่ไม่อยู่ในทะเบียนแสดงเป็น "ค่าอื่น (n)" และคงค่าเดิมไว้
- บอกทุกครั้งว่าการเปลี่ยนมีผลทันที หรือมีผลเมื่อผู้ใช้ล็อกอินใหม่ (spec 2.1)
- การกระทำที่กระทบหลายคนหรือหลายระบบ (ตั้งสิทธิ์หลายคน, ปิดใช้งาน, ลบ, ถอนผู้ดูแล, ล้างสิทธิ์ทั้งระบบ) ต้องมี dialog ที่สรุปผลเป็นตัวเลขก่อนยืนยัน
- การกระทำที่ย้อนไม่ได้ต้องให้พิมพ์ยืนยัน: ลบ → อีเมลของแถว, ล้างสิทธิ์ทั้งระบบ → key ของระบบ
- ผู้ดูแลระบบต้องไม่เห็นแท็บหรือช่องข้อมูลอ่อนไหวเลย ไม่ใช่แค่ปิดไว้
- แถวนักศึกษาและ id ที่ไม่มีอยู่ แสดงหน้า 404 เดียวกัน
- ทุกหน้าที่โหลดข้อมูลมีครบ 4 สถานะ: กำลังโหลด / ว่าง (บอกว่าต้องทำอะไรต่อ) / error (ภาษาคน + ปุ่มลองใหม่) / ไม่พบ

## ข้อมูลตัวอย่าง
ภาพหน้าจอ คู่มือ และตัวอย่างใช้ข้อมูลสมมติจาก `sql/dev-seed.sql` เท่านั้น ห้ามมีชื่อหรืออีเมลจริง

## ก่อนส่งงาน UI
1. ลองที่จอกว้าง 360px, 820px (จุดที่เมนูยุบ) และ 1280px
2. ไล่ใช้ทั้งหน้าด้วยคีย์บอร์ดอย่างเดียว
3. ลองทั้งในบทบาทผู้ดูแลกลางและผู้ดูแลระบบ
4. เทียบกับ `docs/design-c-all-pages.html` ว่าหน้าตาตรงกัน
5. ค้นหา `tracking-` ในไฟล์ที่แก้ ต้องไม่มีกับข้อความไทย
