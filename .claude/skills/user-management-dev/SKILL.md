# พัฒนาระบบจัดการผู้ใช้

`spec.md` ที่ root คือข้อกำหนดหลัก อ่านหัวข้อที่เกี่ยวข้องก่อนเขียนโค้ดทุกครั้ง ถ้าโค้ดจะต่างจาก spec ให้แก้ spec ก่อนและบอกผู้ใช้ ห้ามให้สองอย่างนี้ขัดกัน

## Stack
Next.js 16 (App Router) + TypeScript, Auth.js v5 + Microsoft Entra ID, Prisma (เฉพาะฐาน `usermanagement`), MySQL 8.4, Tailwind CSS 4, Vitest ดูรายละเอียดใน spec หัวข้อ 11

## กฎที่ห้ามพลาด

### ฐานข้อมูลจริง
- **ห้ามแตะฐาน `user` และ `usermanagement` จริงระหว่างพัฒนา** ทุกเว็บของคณะอ่านอยู่ ใช้ `user_dev` และ `usermanagement_dev` ซึ่งอยู่บนเซิร์ฟเวอร์เดียวกัน (skill `dev-database`)
- ห้ามเขียนชื่อฐานตายตัวในโค้ด ใช้ `dbNames()` จาก `src/lib/env.ts` เท่านั้น (เดาจาก `DATABASE_URL` และโหมด หรือ `USER_DB` / `APP_DB` ถ้าตั้งไว้) ห้ามลดตัวกัน `_dev` ในโหมดพัฒนา
- ห้ามเอาข้อมูลจริงเข้า repo, seed, test, ภาพหน้าจอ หรือ log ทั้งชื่อ อีเมล HMAC RFID และเบอร์โทร ใช้ข้อมูลสมมติ
- ห้ามเปลี่ยนโครงสร้าง `user`.`user` (ไม่ `ALTER`, ไม่เพิ่มคอลัมน์) ระบบใหม่ใช้ `user_roles`

### SQL ที่แตะฐาน `user`
- raw query ต่อ `user`.`user` และ `user`.`user_roles` อยู่ใน `src/lib/registry.ts` ไฟล์เดียว
- ระบุคอลัมน์ทุกครั้ง ห้าม `SELECT *` query รายชื่อห้าม select `U_idcard_hmac`, `U_rfid`, `U_tel`
- ชื่อคอลัมน์สิทธิ์ที่มาจาก `systems.column_name` ต้องผ่าน allowlist (`/^U_[a-z]+$/` และมีอยู่จริงใน `information_schema`) ก่อนใส่ backtick ค่าอื่นทุกค่าใช้ parameter
- `DELETE` บน `user`.`user` มีได้ในฟังก์ชันเดียว และต้องมีเงื่อนไขครบตาม spec 4.5.1 ใน `WHERE` (สิทธิ์ทุกคอลัมน์ `IS NULL` และ `NOT EXISTS` ใน `user_roles`) ถ้าลบได้ไม่ใช่ 1 แถวให้ rollback
- ห้าม `UPDATE U_id`
- ตัดช่องว่างและแปลงอีเมลเป็นตัวพิมพ์เล็กก่อนบันทึกและก่อนเทียบ
- ตรวจอักขระ 4 ไบต์ (อีโมจิ) ก่อนเขียนลง `user`.`user` เพราะตารางเป็น `utf8mb3`

### สิทธิ์สองแบบ
ดู `systems.storage` ทุกครั้งที่อ่านหรือเขียนสิทธิ์ ห้ามเขียนแยกกรณีกระจายไปหลายไฟล์ ให้มีฟังก์ชันกลางที่จัดการทั้งสองแบบ

| storage | ไม่มีสิทธิ์ | ตั้งสิทธิ์ |
|---|---|---|
| `column` (9 ระบบเดิม) | คอลัมน์เป็น `NULL` | `UPDATE user SET \`U_xxx\` = ?` |
| `table` (ระบบใหม่และ `users`) | ไม่มีแถว | upsert `user_roles`, "ไม่มีสิทธิ์" = ลบแถว |

ค่าที่ไม่อยู่ใน `systems.levels` ห้ามทิ้งหรือแก้เอง ให้แสดงเป็น "ค่าอื่น (n)"

### ตรวจสิทธิ์ทุก server action
ทำตามลำดับนี้ทุกครั้ง อ่านจากฐานข้อมูล ห้ามเชื่อค่าใน session:
1. ล็อกอินแล้ว
2. บทบาทจาก `user_roles` (`system_key` = `users`): 99 ผู้ดูแลกลาง, 50 ผู้ดูแลระบบ
3. ขอบเขต: ผู้ดูแลระบบแตะได้เฉพาะระบบใน `system_admins` ของตน, ห้ามแตะ `users`, ห้ามแก้สิทธิ์ตัวเอง, ห้ามตั้งสิทธิ์ให้คนที่ปิดใช้งาน, ห้ามแตะแถวนักศึกษา (`U_position LIKE 'นักศึกษา%'` → 404)
4. ค่าระดับอยู่ใน `systems.levels`

ต้องมีผู้ดูแลกลาง (99) อย่างน้อย 1 คนเสมอ ห้ามลดสิทธิ์หรือปิดใช้งานคนสุดท้าย และผู้ดูแลกลางลดสิทธิ์ตัวเองไม่ได้

### Audit log
- การเปลี่ยนทุกครั้งเขียน `audit_log` ใน transaction เดียวกับการเปลี่ยน
- ข้อมูลอ่อนไหวบันทึกแค่ `"changed"` ห้ามบันทึกค่า
- แอปห้าม `UPDATE`/`DELETE` ตาราง `audit_log`

### ข้อมูลอ่อนไหว
- เลขบัตรประชาชน: รับ 13 หลัก ตรวจ check digit แล้วคำนวณ HMAC ด้วย `IDCARD_HMAC_KEY` ฝั่ง server เก็บแต่ผลลัพธ์ (hex ตัวพิมพ์เล็ก 64 ตัว) ห้ามเก็บ log หรือส่งเลขเดิมกลับไปที่เบราว์เซอร์
- ห้าม log request body ทุกกรณี
- คีย์และรหัสผ่านทั้งหมดอยู่ใน `.env` ห้าม commit ห้าม import ในไฟล์ที่ทำงานฝั่ง client

### View และ API สำหรับเว็บอื่น
- `user`.`v_roles` และ `user`.`v_staff` คือข้อตกลงกับเว็บอื่น (spec 8.1) ห้ามลบหรือเปลี่ยนความหมายของคอลัมน์ เพิ่มคอลัมน์ใหม่ได้
- เมื่อเพิ่มหรือย้ายระบบแบบ `column` ต้องแก้ส่วน `UNION ALL` ของ `v_roles` ให้ตรงกับทะเบียนระบบ ไม่งั้นจะได้แถวขาดหรือซ้ำ
- API `/api/v1/roles` (spec 8.2) อ่านอย่างเดียว ห้ามเพิ่ม endpoint ที่เขียนข้อมูล ตอบเฉพาะระบบที่ผูกกับ key และอ่านจาก `v_roles` เหมือนเว็บที่ต่อฐานข้อมูลตรง
- เก็บแค่ SHA-256 ของ API key เทียบแบบ constant-time และห้าม log key หรืออีเมลที่ถาม

### ความเข้ากันได้กับเว็บอื่น
เว็บอื่นอ่านตารางเหล่านี้ตรง ดูข้อตกลงใน spec หัวข้อ 8 ก่อนแก้อะไรที่เปลี่ยนความหมายของข้อมูล เช่น `U_branch` = "สำนักงานคณะ" ต้องตรงทุกตัวอักษร และค่าระดับของ `U_evaluation` คือ 1/50/80/99

## หน้าจอ
- ข้อความภาษาไทยทั้งหมด ฟอนต์ Prompt ห้ามใช้ letter-spacing กับภาษาไทย
- ใช้บนมือถือได้ พื้นที่กดไม่เล็กกว่า 44px
- การกระทำที่มีผลกว้าง (ปิดใช้งาน, ลบ, ตั้งสิทธิ์หลายคน, ถอนผู้ดูแล) ต้องมี dialog ยืนยันที่สรุปผล
- ตั้งระดับสิทธิ์ด้วยตัวเลือกเท่านั้น ห้ามให้พิมพ์ตัวเลขเอง

## ก่อนบอกว่างานเสร็จ
1. รัน `npm run lint`, `npm run typecheck`, `npm test` ให้ผ่าน
2. ถ้าแตะสิทธิ์ การลบ หรือข้อมูลอ่อนไหว ต้องมี test ตาม spec หัวข้อ 10
3. เช็กว่าไม่มีข้อมูลจริงหรือค่าใน `.env` หลุดเข้า diff
